Gold-first Quant Trading OS

黄金量化交易系统

先从 XAUUSD / COMEX Gold 做出最小可运行闭环：数据进来，清洗成可信时间序列，策略把市场状态翻译成信号，回测和风控把信号变成交易票据，最后在面板上人工确认。

边界 自动化到“生成计划 + 排队审批”，真钱执行保留人工确认，不默认全自动下单。
起点 黄金比股票池更窄，适合先打通数据质量、宏观因子、事件冲击、回测和风控。
扩展 同一套接口后续可以接白银、美元指数、债券收益率、BTC、美股 ETF 和 A 股映射。

五大模块

这不是五个孤立页面，而是一个交易生产线。每个模块都要交付可被下游消费的 artifact，避免策略逻辑散落在脚本和聊天记录里。

01

数据获取

先接黄金主数据，再接解释黄金的宏观和事件数据。

  • 价格：XAUUSD spot、COMEX GC futures、GLD ETF。
  • 宏观：美元指数、实际利率、Fed 预期、CPI 日历。
  • 事件：央行、地缘风险、ETF 持仓、新闻叙事。
artifact: raw_snapshots/YYYY-MM-DD/*
02

数据清洗

交易系统最怕“看起来能跑”的脏数据，清洗层要单独可审计。

  • 统一 symbol、交易时区、OHLCV schema 和频率。
  • 标记缺口、异常 spike、重复 candle、供应商漂移。
  • 保存原始数据引用，清洗结果不可覆盖。
artifact: clean_bars/gold_1h.parquet
03

数据分析

从“指标堆砌”收敛成几个可解释的交易状态。

  • 技术面：趋势、突破、均值回归、波动率压缩。
  • 宏观面：实际利率、美元、风险偏好、通胀预期。
  • 事件面：新闻情绪、央行发言、冲击传导链。
artifact: signals/YYYY-MM-DD.json
04

回测 / 实盘 / 风控

策略先被历史和 paper 交易反复羞辱，再允许小资金上线。

  • 回测：交易成本、滑点、walk-forward、参数稳定性。
  • 实盘：paper account、订单队列、审批门、回执记录。
  • 风控：仓位上限、日损失上限、熔断、相关性暴露。
artifact: trade_tickets/YYYY-MM-DD.json
05

交易面板

Dashboard 不是装饰，是交易当天的操作台和审计入口。

  • 看市场状态、信号强度、回测证据、风险预算。
  • 处理待批 ticket：approve、reject、skip、notes。
  • 沉淀 journal，反哺策略路由和风控参数。
artifact: dashboard + journal

八步闭环

沿用你已有的交易管线：`kline → intel → signal → copilot → backtest → risk → executor → journal`。五大模块负责系统边界，八步闭环负责每日运行顺序。

先建 contract，再换供应商

黄金数据源可能会漂移。下游只认 `clean_bars`、`events`、`signals`、`trade_tickets`，不直接依赖某个供应商 SDK。

先 paper，再真钱

任何策略上线前必须经历历史回测、参数稳定性检查、paper account 和小资金限额。Dashboard 的 approve 按钮是风控的一部分。

每个信号必须可解释

黄金经常被宏观叙事驱动。信号不能只有分数，还要有来源、反方证据、失效条件和复盘入口。

先做黄金，不锁死黄金

v1 只做黄金是为了降低复杂度；数据接口、策略接口、风控接口都要为多资产预留字段。

交易面板草图

第一版面板应该像驾驶舱，不像报表站。它每天只回答四个问题：现在是什么状态，系统想做什么，风险能不能承受，最后是谁批准的。

建议落地顺序

  1. 先做黄金数据 contract。 定义 `Instrument`、`Bar`、`Event`、`Signal`、`TradeTicket`、`JournalEntry`，不要先写花哨策略。
  2. 打通单策略 paper 闭环。 用一个趋势/回撤策略跑 `daily pipeline → ticket → manual decision → journal`。
  3. 再接 Dashboard。 面板只读本地产物，先展示状态和待批 ticket，确认有用后再加 broker。
  4. 最后扩资产和实盘。 黄金稳定后再接白银、DXY、债券收益率、BTC 或美股 ETF；真钱先限额、审批门常开。
