# Eval Plan — XBuilderLAB/cheat-on-content (orchestrator / compound)

Evaluator: Mark (repo-evals). Date: 2026-07-05.
Method: **static source inspection of a clean clone + GitHub API only.**
No live end-to-end run (compound skill; requires a real content channel,
platform login sessions, and a multi-day retro window). Score is therefore
ceiling-capped at `usable` / Available by the compound-layer rule.

## What This Repo Claims

The central tension is **marketing vs implementation**:

- Marketing (README): "zero to 1M followers in a month", "it predicted this line",
  quantum-fate framing → unfalsifiable growth promises.
- Implementation (SKILL.md + sub-skills + hooks + protocols): a rigorous
  calibration loop — blind prediction, immutable prediction log, isolated blind
  scorer, full-re-score rubric bump with cross-model audit, schema migrations.

## What We Will Validate (claim-by-claim)

### Mechanism — verifiable by reading the code (expected PASS)
- **claim-001** — prediction immutability enforced by a real PreToolUse hook
  (`hooks/prediction-immutability.sh`).
- **claim-002** — blind scorer context isolation + hard-refusal list
  (`skills/cheat-score-blind/SKILL.md`).
- **claim-005** — 15 sub-skills exist + router table dispatches by trigger
  (`SKILL.md`, `install.sh`, `wc -l skills/*`).
- **claim-006** — rubric bump = full re-score + rank-consistency + cross-model
  audit (`shared-references/bump-validation-protocol.md`).
- **claim-007** — 1.0→1.4 schema migration chain + `/cheat-migrate`
  (`migrations/registry.md`).
- **claim-008** — hype quarantined to README, ✅/⬜ honesty markers (`SKILL.md`).

### Install — static read only (PASS with concerns)
- **claim-009** — `install.sh` clean/reversible but symlinks into live skill dir;
  not executed in a clean sandbox per the no-live-mutation rule.

### Efficacy — deliberately skipped (UNTESTED, unfalsifiable / needs longitudinal run)
- **claim-003** — "1M followers in a month" — unfalsifiable n=1 anecdote.
- **claim-004** — "judgment 10× sharper by month 3" — needs months of logged
  live runs on a real channel.

### Credential-gated — deliberately skipped (UNTESTED)
- **claim-010** — perf-data adapters (douyin/xhs/linkedin/bilibili) — need
  Playwright + platform login; not verifiable without real credentials.

## How Many Times We Will Test

- Each mechanism claim: read the load-bearing source file(s) once, record a
  CONFIRMED/PLAUSIBLE verdict with a repo-relative evidence ref.
- Efficacy + credential claims: not run (documented skip_reason on each claim).

## What Counts As Passing

- Mechanism claim passes if the enforcing code / protocol actually exists and
  does what the README says (not merely asserted).
- Efficacy claims cannot pass without a longitudinal live run; recorded untested.

## If Everything Passes, What We Can Trust

- Achieved trust level: `usable` / 🛠 Available — the *machinery* of the
  calibration loop is real and honest; the *outcome* (does it grow you / sharpen
  you) is unproven here.
- Stretch (would require a separate run): one sandboxed end-to-end cycle
  (init → predict → publish → retro) to lift `core_layer_tested` and clear the
  compound ceiling.
- Remaining risk: adapter fragility (anti-scraping), rubric only calibrated for
  one Chinese opinion-video creator, months-long commitment before any payoff.
